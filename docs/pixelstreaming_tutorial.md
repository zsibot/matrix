# Pixel Streaming 2 Quick Guide

[README](../README.md)

The current `uesim` project enables the Unreal Engine `PixelStreaming2` plugin and includes Epic's web-server bootstrap directory at:

```text
<UESIM_SOURCE>/Samples/PixelStreaming2/WebServers
```

The MATRiX documentation repository does not contain that directory. Run these steps from a licensed Unreal/`uesim` source checkout, or use the server bundle supplied with your packaged build.

## 1. Prepare the signalling and web server

On Linux:

```bash
cd "<UESIM_SOURCE>/Samples/PixelStreaming2/WebServers"
./get_ps_servers.sh
```

The bootstrap script downloads the matching server sources and dependencies. Review its output for the generated signalling-server path; Epic can change the generated directory layout between engine versions.

## 2. Start the server

Start the signalling/web server using the platform script generated by the previous step. A common Linux layout is:

```bash
cd "<UESIM_SOURCE>/Samples/PixelStreaming2/WebServers"
./SignallingWebServer/platform_scripts/bash/start.sh
```

If that path is not generated, use the path printed by `get_ps_servers.sh` instead. Keep the terminal open and record the HTTP and streamer ports from its output.

## 3. Start MATRiX as a streamer

If the packaged launcher exposes a Pixel Streaming switch, enable it before starting the simulation. For editor or command-line builds, configure Pixel Streaming 2 using the launch arguments supported by the exact Unreal Engine version and point the streamer at the running signalling server.

The plugin being enabled in `UeSim.uproject` does not by itself start the web server or guarantee that a particular release UI exposes the switch.

## 4. Connect from a browser

Open the HTTP URL printed by the signalling server. Do not assume port 80: server presets, reverse proxies, and newer server versions can use another port.

For remote clients, allow only the required HTTP/WebSocket/streamer ports and configure TLS and authentication before exposing the service to an untrusted network.

## Troubleshooting

- Verify the simulator renders locally before debugging the browser path.
- Confirm the streamer appears in the signalling-server log.
- Check that the browser URL and streamer endpoint refer to the same server.
- Check firewalls, NAT, WebSocket proxies, and TLS configuration.
- Keep the web-server bundle aligned with the Unreal Engine version used to package UeSim.
